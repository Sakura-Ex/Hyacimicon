# 对局会话接口设计

状态：设计稿。对应现有玩家界面和运营模拟，覆盖从开局到整局结算。浏览器、Tauri 和模型客户端可以按同一份 [类型声明](contract.d.ts) 对照数据。路线、数值、已实测和待核对规则见[对局规则记录](README.md)。

## 调用入口

| 操作 | 请求 | 成功结果 |
| --- | --- | --- |
| `createMatch` | 账号 ID、规则版本、敌人难度、负面词条数量、随机源配置 | 创建对局，固定本局使用的账号配置版本，由手动控制，返回投资环境待选的初始快照 |
| `getMatch` | 对局 ID | 当前可见快照，适合打开界面、重连和模型决策前读取 |
| `executeAction` | 对局 ID、预期版本、动作 ID | 校验控制权、版本和动作，返回提交后的快照 |
| `setController` | 对局 ID、预期版本、目标控制方 | 完成交接并返回新的快照。交接本身增加版本 |
| `subscribeMatch` | 对局 ID | 首条消息返回当前快照，随后推送该局已提交的操作、控制权变化和战斗状态 |

对局由一个 Rust 服务实例持有。Tauri 将调用参数和返回值转发给该服务，每次调用表达一次完整的业务操作。模型在独立进程时，通过本地连接访问同一实例，具体传输方式由接入方式确定。批量训练可以让每个环境维护各自的会话。

现有 Tauri `player_match` 和 `player_execute_match_command` 是桌面适配入口。接入时，账号选择页保存返回的 `matchId`，当前 `commandId` 映射到 `actionId`，`MatchPort` 将会话快照转成页面所需的显示值。模型直接读取结构化动作。现有实测反馈和常规战斗看板沿用各自的入口。

## 与运营模拟的关系

`codex/operation-simulator` 的 `72cc194` 提供 `core/operations` 运营核心，以及 `apps/player/operations` 本地网页服务。运营核心负责商店、角色位置与升星、经济、投资和节点推进。接入时由会话服务调用经过规则核对的运营方法，运营状态继续由同一套规则更新。

现有网页服务通过 `/api/sessions/{id}/actions` 执行动作，`advance_node` 使用预设进度同步结算，再返回网页状态。这里定义的会话契约在它之上补充局面版本、合法动作、控制权和订阅，并将真实战斗启动与异步结果结算交给战斗交接接口。现有 `state_json` 含随机种子与调试数据，模型观测按本契约从可见状态构造。补给节点、待选限制及战后结算规则以本模块已核对的设计为接入验收依据。

## 版本、执行与通知

- `matchId` 标识一局。`revision` 是从 0 开始递增的整数。每次生效的操作、控制权交接或战斗异步写入提交一个新版本。同一控制方的重复交接视为无变化，返回当前快照。
- 当前控制方由服务记录。调用方身份由接入层提供，模型按绑定的 `modelId` 校验。拥有交接权限的手动调用方可以收回控制。已订阅的观察者在交接后继续收到变化。
- 动作 ID 的有效范围是某局的一个版本。动作携带结构化类型和目标，调用方用它选动作，执行请求只提交 ID。服务在同一次写入中校验并执行。失败保留版本和局面，例如 `revisionConflict` 表示应重读，`controllerMismatch` 表示操作来自当前没有控制权的一方。
- 订阅在同一会话同步点取得初始快照并注册。随后每个已提交版本发一条通知。客户端按版本处理，收到较老的快照就保留本地较新版本。断线后重新订阅即可取得完整现状；通知里的操作摘要供监控面板展示。

例如，模型接管后在第 `8` 版发现 `buy-3` 对应商店第 3 格的报价，调用 `executeAction`，输入 `{ "matchId": "run-1", "revision": 8, "actionId": "buy-3" }`。服务提交第 `9` 版，模型直接拿到新快照；Tauri 订阅收到 `actionApplied` 后，也可以读第 `9` 版刷新界面。玩家交还后，模型用第 `9` 版提交的后续动作会被拒绝。

## 局面字段

| 字段 | 含义 |
| --- | --- |
| `route`、`position` | 路线编号和类型、当前显示节点、从零开始的路线位置，以及已正式进入的常规节点计数。候选选择阶段可以显示目标节点，入节点计数稍后增加 |
| `phase` | 互斥阶段。候选、剩余刷新、进行中的战斗 ID 等随相应阶段返回。投资策略、补给、主角光环还返回当前是选择还是备战视图 |
| `rival`、`opponents`、`affixes`、`environment`、`companion` | 当前公开的竞争对手身份、各位面的敌人与首领预览、负面词条、投资环境、伙伴 |
| `preparation` | 队伍、格位上限、商店、金币、经验、血量、连胜、晶矿、羁绊进度、机制以及历次投资和光环。角色身上和物品栏的装备各自返回实例 ID、定义 ID 和数量。开局尚未产生备战数据时为 `null` |
| `legalActions` | 本版本可选的动作和目标。像同名角色、相同装备和同色晶矿，通过会话内实例或堆叠 ID 区分。羁绊提供的动作通过 `source` 标出对应羁绊 |
| `latestSettlement` | 最近一次结算的节点、来源和血量、金币、经验、晶矿明细。下一次结算前可继续读取 |

接口仅返回当前已揭示的信息。开局预览按位面列出对手，具体节点的敌人在游戏揭示后进入 `revealedEnemies`。未开启晶矿只显示品质和数量。隐藏牌池、未来报价、晶矿内容和随机状态由 Rust 环境保存。账号或规则版本的公共图鉴提供角色、装备和羁绊的展示资料，局面通过定义 ID 引用。

## 阶段与动作

动作名对应类型声明中的 `MatchAction.kind`。投资策略、补给、主角光环进入待选时，`phase.view` 为 `selection`。点击 `returnToPreparation` 后变为 `preparation`，点击 `returnToSelection` 后回到 `selection`。两边都通过 `executeAction` 切换，服务更新版本和合法动作。两次切换均保留当前待选阶段、`selectionId`、候选和刷新次数。

| 阶段 | 可执行动作与状态变化 |
| --- | --- |
| 投资环境待选 | `refreshChoice` 每个候选格一次；`chooseInvestmentEnvironment` 确认后进入 `1-1`，生成初始阵容、商店和晶矿 |
| 常规备战 | `buy`、`sell`、`refreshShop`、`lockShop`、`buyExperience`、`move`、`equip`、`combine`、`useItem`、`openCrystal`，以及当前可用的羁绊操作。准备好后 `startBattle`。符合条件的首领阶段先提供 `openSpotlight` |
| 投资策略待选 | 选择视图可 `refreshChoice`（每格一次且保持品质）、`chooseInvestmentStrategy` 或 `returnToPreparation`。备战视图可 `openCrystal` 或 `returnToSelection`。确认策略后正式进入同编号战斗节点，发放入节点收益 |
| 补给待选 | 选择视图可 `refreshSupply`（整组一次）、`takeSupply` 或 `returnToPreparation`。备战视图可 `openCrystal` 或 `returnToSelection`。必须从五组中选一组，领取和自动推进在一次写入内完成 |
| 主角光环待选 | 选择视图可 `refreshChoice`（更换单个候选并扣本轮刷新价）、`chooseSpotlight` 或 `returnToPreparation`。备战视图可 `move`（含备战席与场上互换）、`openCrystal` 或 `returnToSelection`。选择后回到首领备战，旧光环留作难度记录，最新光环效果生效 |
| 幕后茶歇 | `chooseTeaBreak` 确认茶歇选项；`claimTeaBreakReward` 领取晶矿及正常战斗奖励，经验增量为 0。设计先将选择和领取表达为两个阶段，联调核对实际操作是否自动合并 |
| 战斗中 | `restartBattle` 从头重跑并沿用本次进入的随机序列；`leaveBattle` 保留运营局面、进入暂离。战斗内技能和行动由战斗模块处理 |
| 战斗暂离 | `move` 和 `reenterBattle`。重进按调整后站位从头开始，并采用新随机序列 |
| 战斗暂不可用 | 战斗模块报技术错误时显示消息，可从同一配置 `restartBattle` 或 `leaveBattle`。该错误不扣血、不发奖励，也不推进节点 |
| 整局结束 | 读取和订阅最终快照，结束原因区分通关与血量耗尽 |

`move` 由 Rust 判断是移到空格还是与目标格上的角色互换。`equip` 提供道具和角色实例，服务判断直接装备或触发身上合成。`combine` 提供两件物品的 ID，`useItem` 的目标按合法动作指定角色或装备，覆盖普通扳手、精密扳手、冶金炉和其他可用消耗品。晶矿奖励在开启成功后才公开；备战席满 9 格时不提供开启动作。

羁绊提供的操作由 Rust 在常规备战放入 `legalActions`，并标明羁绊来源。投资策略、补给或主角光环待选时，即使返回备战视图，也不开放羁绊操作。能用已有的购买、使用物品或候选选择表达时，复用对应动作；需要其他参数或行为时，为该玩法增加明确的动作类型。玩家和模型都通过 `executeAction` 提交。

羁绊选择包含 `choiceId`、当前选项和选择模式。`once` 通过 `chooseMechanism` 提交选项，确认后即锁定，局面保留已选结果。`changeable` 表示可以通过羁绊旁的入口反复打开、调整和确认。具体羁绊的选择内容和触发条件待规则核对。

1. `openTraitChoice` 打开入口。备战阶段返回 `openTraitChoice`，其中的 `draftOptionId` 初始取当前选项 `selectedOptionId`。
2. `selectTraitOption` 改变待确认的选项，当前生效的 `selectedOptionId` 保持原值。
3. `confirmTraitChoice` 应用待确认项并关闭入口。有当前选项时，可省略第 2 步直接确认，保留原效果。

这三个动作由 `executeAction` 执行。模型能观察入口是否打开、待确认选项和实际生效选项，并据此选择继续修改或确认。

## 战斗交接与结算

对局服务组装本场单位、装备、站位和本局修正，给战斗模块发送 `BattleStart`。每次启动、直接重开或暂离后重进生成新 `attemptId`，是否沿用随机序列由对局服务决定。战斗模块可以用同一个 ID 上报完成或技术错误。只接受当前有效尝试的回执，迟到或重复回执保持现状。

战斗模块回传胜负、是否打满或未满百分比，以及本次尝试的晶矿掉落。同时分别保留胜负与进度，以表达奖励关等由战斗模块按规则给出的特殊结果。进度使用闭开区间 `[0, 100)` 表达未满，打满使用 `complete`。服务用数值进度判门槛。

收到有效战斗结果后，对局服务在同一次写入内结算并发布新快照。

1. 根据位面和进度计算失血，先四舍五入，再处理遭遇 25% 和首领 33% 的门槛。打满时失血为 0。
2. 扣血后应用固定回复 2 点和其他变化。最终血量取血量上限与计算结果的较小值。最终血量 `≤ 0` 时结束对局。
3. 按开战前金币计算利息，按更新后的连胜结算连胜奖励，并应用基础金币、经验和本次尝试的晶矿掉落。
4. 依据对局结局或路线进入下一阶段。下一阶段若为投资策略，先展示本场结算结果，等选定策略后再正式进入。

## 联调验收

- 手动购买一次，脚本接管同一局并选一条合法动作，界面接收通知显示变化。交还后玩家可继续，交还前准备的模型指令被拒绝。
- 上一场战斗结束后显示金币和晶矿，投资策略确认前保持入节点收益未发放，确认后只发一次。
- 补给候选可整体刷新一次，领一组后自动推进，补给位置保留在路线中，触发计数保持原值。
- 投资策略、补给、主角光环都能从选择返回备战，再回到原选择。模型能观察到每次切换及更新后的合法动作。候选和剩余刷新次数保持原值。补给与投资策略备战时只可开晶矿，主角光环备战时还可换位。
- 羁绊满足条件时，在常规备战下发带羁绊 ID 的动作。一次性选择确认后锁定。可更改选择打开后可直接确认原选项，也可换选后确认。换选只改变待确认项，生效选项在确认时更新。三个待选阶段及其备战视图均关闭羁绊操作。
- 直接重开使用同一随机序列，暂离再进使用新随机序列。旧战斗结果晚到不改变局面，最终尝试只结算一次。
- 战斗进度失血的设计使用四舍五入，并验证门槛、回血上限和最终血量刚好为 0 的情况。

待实测项继续维护在[规则记录](README.md)。羁绊专属机制的独有操作随规则核对扩展。战斗帧和行动轴留在战斗模块接口，对局快照只引用当前战斗尝试。
