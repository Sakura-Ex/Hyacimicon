# 运营模拟

状态：首版已实现，接入最新角色、羁绊和节点数据。日期：2026-11-16。

本模块按 M3.2 的范围实现不含作战过程的整局运营环境。它负责商店、金币与经验、角色牌池和合成、投资环境、投资策略、难度词缀、节点推进和战斗结果结算。具体战斗由可替换的战斗进度提供器给出结果，本模块只处理战斗结束后的运营状态。

## 已实现

- 10 级商店费用概率，以及公开记录的五种角色费用和每种角色的牌池数量。
- 商店自动刷新、锁店、免费刷新、金币刷新、购买和出售。
- 等级经验表、购买经验、团队规模与三星角色合成。
- 开局角色只从 1～3 费抽取；购买和合成后的角色进入备战席，可手动部署到前台或后台。
- 上阵总人数不超过商店等级，前台最多 4 人、后台最多 6 人、备战席最多 9 人。
- 按真实编号排列的 20 节点模板：第一位面 8 个、第二位面 6 个、第三位面 6 个；统计为 5 个奖励、9 个战斗、3 个遭遇和 3 个首领节点。
- 固定节点生成三个不重复投资策略，应用当前规则包支持的金币、经验、刷新、延迟收益、利息上限和强度效果。
- 开局投资环境和敌人词缀。支持指定词缀，或按难度随机生成。
- 使用游戏原生“敌人难度 + 词缀数量”两个参数配置难度，敌人难度范围为 1～211。
- 玩家观测与商店隐藏牌池分离；相同种子和动作产生相同回放。
- 可注入的战斗进度接口。默认返回 100%，100% 判胜，低于 100% 判负。
- 游戏式本地网页，按顶部节点路线、左侧羁绊、中央前后台、底部商店组织，并使用数据快照中的角色与羁绊图标。
- 商店可收起切换为 9 格备战席；前台、后台和备战席角色支持拖拽上下场。

网页启动时从 `hsr-currency-wars-data` 读取 `encyclopedia-4.6.54-85a54e5115f8` 快照，当前为 61 名角色和 38 个羁绊条目，并校验对应文件的 SHA256。主仓库不复制完整图鉴数据。词缀、投资环境和投资策略仍使用规则包中已实现的结构化效果。

## 运行

网页手动操作：

```powershell
uv run python -m examples.operations.web
```

启动后浏览器会打开 `http://127.0.0.1:8765/`。服务自动查找 `hsr-currency-wars-data`；也可通过 `--data-root` 指定仓库路径。网页使用本地内存保存对局，关闭服务后不会保留会话。操作和检查说明见[网页操作与检查](web-interface.md)。

单局运行：

```powershell
uv run python -m examples.operations.simulate --enemy-difficulty 20 --affix-count 2 --environment silver_age --seed 7
```

通过 `--battle-progress 0-100` 指定自动运行使用的战斗进度，默认 `100`。

批量评估：

```powershell
uv run python -m examples.operations.simulate --enemy-difficulty 40 --affix-count 4 --environment silver_age --seed 7 --runs 1000
```

验证：

```powershell
uv run python -m unittest discover -s tests -v
uv run ruff check .
uv run ruff format --check .
```

## 已知边界

本模块没有模拟角色技能、行动顺序、站位或伤害。抽象阵容强度只用于调试，不决定节点胜负；胜负由可替换的战斗进度提供器给出。

当前已接入完整角色和羁绊目录，但角色特殊机制、装备、73 个最新投资环境和 304 个投资策略的结构化效果尚未全部实现。部分基础经济常量仍使用模拟假设值，详见[数据来源与验证](data-provenance.md)。

设计说明见[运营模拟设计](design.md)。
