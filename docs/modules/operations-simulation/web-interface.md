# 网页操作与检查

状态：游戏式界面首版可用。日期：2026-11-16。

## 用途

网页用于手动执行货币战争的局外运营操作，并检查商店、资源、投资和节点结算是否符合预期。布局参考游戏备战界面，分为顶部节点路线、左侧羁绊、中央前后台、右侧工具列和底部商店。战斗过程、动画和伤害计算不在此模块中运行。

## 启动

```powershell
uv run python -m examples.operations.web
```

服务默认监听 `127.0.0.1:8765` 并打开浏览器。仅在本机使用，不需要额外安装网页依赖。需要指定端口时：

```powershell
uv run python -m examples.operations.web --port 8877 --no-open
```

指定私有数据仓库位置：

```powershell
uv run python -m examples.operations.web --data-root E:\hsr-ai\hsr-currency-wars-data
```

省略 `--data-root` 时，会从当前工作目录和父目录查找 `hsr-currency-wars-data`。

## 可执行操作

- 创建指定敌人难度、词缀数量、投资环境、随机种子和初始战斗进度的对局。
- 锁定或刷新商店。
- 购买商店角色、出售已有角色。
- 购买经验并查看升级结果。
- 在阵容工具中把角色部署到前台、后台或备战席，并查看容量限制。
- 收起底部商店以显示备战席，并直接拖动角色在备战席、前台和后台之间移动。
- 在投资节点选择三个候选策略之一。
- 修改后续节点的战斗进度并结算当前节点。
- 查看生命、金币、等级、经验、连胜、免费刷新和角色状态。
- 查看节点结果、动作记录、剩余牌池、阵容强度和节点强度。
- 导出当前会话 JSON，用于保存检查结果。

网页只显示后端返回的状态。每个动作都会重新检查资源、阶段和合法性，非法操作不会修改对局。

## 战斗进度

初始值和新对局默认值是 `100%`：

- `100%`：节点胜利，保持或增加连胜。
- `0%～99%`：节点失败，中断连胜并按节点规则扣除生命。

修改战斗进度不消耗商店、投资或奖励随机数。节点结果记录实际进度和提供器标识。

## 检查信息

左侧羁绊栏把当前阵容涉及的羁绊分为“已激活”和“未激活”，显示数量、分类和下一档位。中央区域按玩家部署显示前后台，商店与角色卡读取最新图鉴头像。底部“收起商店”按钮切换 9 格备战席，角色卡可通过拖拽在备战席、前台和后台之间移动；容量仍然由后端检查。

右侧“检查”区域额外显示：

- 当前抽象阵容强度。
- 当前节点敌人强度。
- 每种角色的剩余牌池数量。
- 随机种子和战斗进度提供器。

这些信息用于确认规则运行，不代表游戏内一定可见。

## 当前限制

- 对局保存在网页服务进程内存中，服务重启后丢失。
- 当前只有固定战斗进度提供器。
- 角色部署在“阵容”工具中操作；购买后不会自动替换当前阵容。
- 最新角色和羁绊已从图鉴快照读取；角色特殊机制、装备、投资环境和投资策略的结构化效果仍需继续接入。
- 网页支持单机手动检查；未来训练程序直接调用后端环境，不经过网页接口。
