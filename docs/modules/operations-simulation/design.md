# 运营模拟设计

状态：首版已实现。日期：2026-11-11。

## 目标与边界

运营环境回答的问题是：在给定账号、难度、开局词缀和当前局面下，一次局外操作会怎样改变后续资源、阵容和整局通关概率。

本模块不计算角色伤害、行动值或技能事件。战斗被替换为一个可替换的概率接口：

```text
抽象阵容强度 + 节点强度 + 难度修正 + 词缀修正
        ↓
本次节点胜负概率
        ↓
生命、金币、连胜和节点进度变化
```

该概率接口以后可替换为已验证的战斗模型或真实对局统计，不需要修改商店、投资和节点结算规则。

## 状态与观测

环境内部保存的完整状态包括：

```text
OperationEnvironment
├── 生命、金币、利息上限、连胜
├── 当前节点、位面、难度和开局词缀
├── 完整角色牌池、商店、等级和经验
├── 已拥有角色与星级
├── 已选投资环境、投资策略和待发放收益
├── 完整随机源
└── 已完成的节点结果
```

`observe()` 只返回玩家当时能看到的内容：

```text
RunObservation
├── 当前可见节点信息
├── 当前生命、金币、等级、经验和连胜
├── 商店五个位置、锁定状态和免费刷新次数
├── 当前上阵与已拥有角色
├── 当前三个投资策略
├── 已选投资和公开的敌人词缀
└── 抽象阵容强度与当前胜率估计
```

牌池剩余数量、未来商店和随机源不进入观测。

## 商店与角色

商店包含五个位置。每次节点开始自动刷新，玩家可以锁定商店并跨节点保留。

费用概率按 Wiki 记录的 Lv.1 至 Lv.10 表维护。每个位置先抽取费用，再按该费用下每个角色剩余卡牌数加权抽取角色。

角色卡数量：

| 费用 | 每名角色卡牌数 |
| --- | ---: |
| 1 费 | 30 |
| 2 费 | 25 |
| 3 费 | 18 |
| 4 费 | 10 |
| 5 费 | 9 |

购买消耗金币和牌池卡牌。出售返还对应角色消耗卡牌数量的金币，并将卡牌归还牌池。三个同角色同星级实例自动合成一个更高星级实例。

## 等级和经验

首版从 Lv.3 开始；1 至 2 级仍保留费用概率和升阶表项，便于导入其他开局场景。

经验门槛集中在 `GameRules.xp_to_next_level`。购买经验、投资策略免费经验和升级后触发效果都调用同一套等级推进代码，避免策略额外维护等级。

团队规模等于当前商店等级。环境中按抽象强度选择最高的若干角色上阵；真实站位、前后台赋能和具体羁绊效果留给后续阵容模块。

## 经济结算

节点结束后统一按以下顺序更新：

1. 判定节点胜负。
2. 胜利时增加连胜，失败时清零。
3. 获得基础金币和当前金币利息。
4. 胜利时增加连胜奖励。
5. 失败时扣除节点生命值。
6. 生命归零时结束对局。
7. 最后一个首领节点完成时结算整局。

利息步长、上限、基础金币和失败扣血集中在 `GameRules`。公开资料未确认的值在规则包元数据中列为假设。

## 投资环境与投资策略

投资环境在开局决定经济或阵容起始条件。当前支持的开局效果包括：

- 初始角色、金币或每个位面的金币。
- 固定投资策略品质。
- 奖励节点收益倍率。
- 移除一个开局词缀。
- 每个节点累计阵容强度。

投资策略在固定节点以三个不重复选项出现。策略品质决定基础敌人难度增量，具体策略效果再应用即时金币、经验、免费刷新、利息上限、延迟金币、购买锁定、阵容强度或生命金币交换。

延迟收益以触发节点保存在环境中，回放时按节点索引发放一次。玩家中断或结束对局后，未触发收益不结算。

## 开局词缀与难度

难度预设包含：

```text
基础敌人强度
每节点强度增长
随机开局词缀数量
```

词缀保留原始名称、描述和数值影响。当前模型把词缀转换为：

- 初始生命变化。
- 敌人强度倍率或位面倍率。
- 阵容总强度倍率。
- 按角色费用或星级的强度倍率。
- 高等级购买经验的额外金币。
- 奖励收益倍率。

纯战斗内部词缀如果没有运营侧可观测影响，不强行编造经济效果。

## 抽象胜率

当前用平滑比较器连接阵容强度和节点强度：

```text
ratio = team_power / enemy_rating
p_win = 1 / (1 + exp(-temperature × (ratio - 1)))
```

`temperature` 越大，强度差对胜率的影响越明显。该式只作为首版策略比较器。正式评估前需要替换为按难度、节点和阵容校准的战斗概率模型，并报告校准误差。

## 回放与扩展

所有随机过程使用调用方传入的 `random.Random`。相同规则包、难度、环境、词缀、随机种子和操作序列产生相同节点结果。

扩展数据时优先保持以下接口：

- 新角色写入 `UnitDefinition`，不修改市场算法。
- 新词缀写入词缀效果字段，不把名称判断散落到环境。
- 新投资效果先增加显式效果字段和结算测试，再加入规则包。
- 战斗模型通过替换阵容强度和敌人强度计算接入，不进入商店或投资代码。
