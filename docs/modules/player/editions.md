# 玩家版与研究版

Hyacimicon 提供两个应用入口，共用书册装帧、账号导入与档案界面、基础显示名称及窗口代码。

| 能力 | 玩家版 | 研究版 |
| --- | --- | --- |
| 账号导入与管理 | 已实现 | 已实现 |
| 实战局面手动记录 | 已实现，表单录入 | 原有实战回填 |
| 图像识别与模型推理 | 待接入 | 待接入真实模型 |
| 模拟对局、模型观战 | | 保留演示服务和正式服务适配器 |
| 战斗阵容预览与示例回放 | | 已有预览，正式战斗服务待接入 |
| 随机账号生成 | | 已实现 |
| 游戏图像下载与缓存 | | 保留研究版原有能力 |

## 构建与启动

在 `apps/` 安装 `npm ci` 后执行：

| 操作 | 玩家版 | 研究版 |
| --- | --- | --- |
| 浏览器预览 | `npm run dev`（1420） | `npm run dev:research`（1421） |
| 前端构建 | `npm run build`（`dist/`） | `npm run build:research`（`dist-research/`） |
| 桌面开发 | `npm run tauri dev` | `npm run tauri:research:dev` |
| Windows 打包 | `npm run tauri build` | `npm run tauri:research:build` |

玩家版独立入口为 `apps/src/player-main.ts`，研究版入口为 `apps/src/main.ts`。Vite 按构建模式选择入口；研究版 Tauri 配置使用独立应用标识、前端目录和可执行文件名，开启 Rust `research` 特性。两版生成到各自的 Cargo 目录：玩家版 `apps/src-tauri/target-player/`，研究版 `apps/src-tauri/target/`。玩家版默认不编译随机账号生成与游戏图像下载模块。账号导入仍使用内置行迹绑定；账号展示读取名称、ID 和命途对照，并不读取完整游戏数值文档。

研究版继续读取程序旁的 `accounts/` 目录。如果安装路径变化，将旧程序旁的 `accounts/` 复制到新研究版程序旁即可。玩家版的账号在程序旁的 `player-accounts/` 保存，已有账号可通过研究版导出统一账号 JSON，再导入玩家版。

三个名称对照文件 `character-names.tsv`、`light-cone-names.tsv` 和 `relic-set-names.tsv` 位于 `apps/src-tauri/`，初始内容取自原项目 4.7 S2 的角色、光锥、遗器资料（`66103e32` 中的 `docs/game-data/`）。仅保留展示使用的 ID、名称和角色命途。版本更新时依据对应规则资料同步名称与 ID，确认条目唯一、名称非空，非必要的属性和倍率继续留在规则数据中。

## 玩家版实战局面

打开「对局」书签，按实际游戏画面填写本局标识、节点、阶段、阵容各格、五个商店报价、资源与候选信息。数值未知时留空；记录节点变化、购买、刷新、战斗结算等已经发生的结果，不由程序推演下一局面。

点击「记录当前局面」将本次草稿保存为一条独立记录。记录按账号和递增版本保存在本地 WebView 存储；未绑定账号也可记录。重新进入时读取最新记录，使用历史条目的「查看」载入对应草稿，「新对局」清空草稿并保留历史。错误的数值或损坏的历史会提示原因。

当前录入表单用于采集可见事实，角色、装备和候选内容允许文本记录。模型输入编码、稳定条目 ID、合法动作映射及识别结果确认待模型契约确定后接入；现阶段建议区显示模型未接入，不会提供演示建议。

## 研究版

使用已有[对局工作台](match.md)、[会话适配器](match-commands.md)、随机账号生成、观战及战斗预览。研究版的模拟对局由环境推进；真实模型和正式战斗服务仍按各模块实施状态接入。
