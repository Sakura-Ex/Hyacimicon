# Windows 玩家界面

[Hyacimicon](../../../apps/) 使用 Tauri 2、TypeScript 和 Lit。账号、对局和战斗在同一本书中切换。Windows 桌面版可导入、生成和管理本地账号。浏览器提供离线预览。对局支持开局、备战、模型观战和终局演示，战斗书签提供阵容预览。

## 启动

在 Windows 安装 Node.js 22.12 及以上版本、npm、Rust MSVC 工具链、Visual Studio C++ Build Tools 和 WebView2。在仓库根目录运行：

```powershell
cd apps
npm ci
npm run tauri dev
```

`npm run dev` 在浏览器预览，`npm run build` 检查类型并构建页面，`npm run tauri build` 生成 Windows 程序和 NSIS 安装包。

书封、折口与纸层共用可缩放的矢量轮廓，侧边书签由 CSS 绘制。桌面窗口启动时按 1700 × 960 的书册比例套入当前屏幕宽、高各 75% 的区域。启动后窗口大小固定，标题栏保留拖动、最小化和关闭。程序读取书本实际显示边界，按物理像素对齐当前屏幕中心，右侧书签和透明留白不参与计算。安装包包含 [apps/public](../../../apps/public/) 下的页首花饰与界面图标、应用图标和两套 Noto SC 字体，字体许可位于构建产物的 `licenses/`。

各界面共用书册、标题区、横线和书签的尺寸。打开账号子页或切换战斗模式时，这些位置保持固定。滚动条隐藏。角色列表、已保存账号和生成候选列表可用滚轮、键盘或按住鼠标拖动，列表标题和搜索框留在原位。角色资料、行迹与装备、对局内容、生成表单和战斗详情各自滚动。对局操作按钮、导入确认和生成提交留在各自内容区的下方。

### 装帧验收

修改书封、纸页或书签时，按 1700 × 960 画幅对比调整前后的窗口截图，核对页宽、中缝位置、粉色页缘、页首花饰与书签外伸长度。检查三枚书签的根部伸入右页纸层，封板只在书签间隙露出。更换显示倍率后复查接缝及书外透明像素。

## 设置与开发预览

1. 点标题栏「设置」，打开「开发者模式」。该开关保存在当前设备。
2. 点「开发预览」或按 `Ctrl+Shift+D`，搜索或选择要检查的界面。搜索只剩一个结果时，按 Enter 直接打开。
3. 点「退出预览」回到进入前的页面。切换书签也可退出预览并打开所选书签。

账号样例覆盖角色档案、空账号、导入、生成和账号管理。对局样例覆盖开局、备战及满员、各位面进度、待选与返回备战、光环、羁绊、回填、观战及终局。战斗样例覆盖常规、货币战争阵容和可翻页的示例回放。

开发者模式在 Release 中也可开启。预览使用独立的演示账号和对局，退出后丢弃预览操作。战斗中样例停留在初始画面以便查看，可用重开或暂离继续操作。

## 添加账号

在角色档案点“添加账号”，在右侧工具区切换文件导入或随机生成。添加账号和账号管理共用右侧的“返回档案”按钮。

- **文件导入**。选择或拖入 reliquary-archiver 的 Fribbels v4 JSON，或应用导出、生成器产出的统一原始账号 JSON。[account-core](../account/README.md) 检查格式、练度和装备关系。右页显示角色、光锥、遗器、闲置库存数量以及导入提示。填写名称后点“导入并保存”，程序保留原文件、统一账号及可用的来源报告。
- **随机生成**。角色数量必填，支持 0 和内置资料允许的持有规模。可设置目标金数、五星统一星魂与专锥叠影、遗器质量及有效词条区间。右页可配置核心、角色池、光锥池、金数类别、集中度、角色覆盖和搜索预算，也可编辑或载入 [account-generator 请求 JSON](../account-generation/account-generation.md#生成条件)。种子可留空由程序生成，也可填写无符号 64 位整数。程序保存完整请求、实际种子、生成器版本、资料快照和结果统计。

保存成功后切换到新账号，显示原始练度、行迹和当前装备。“管理”可查看已保存账号及报告、改名、导出 JSON、确认删除，或用保存的请求和种子再生成。浏览器预览可查看界面，桌面版负责实际解析、生成和写入。

### 本地账号目录

每个账号保存为程序所在目录下的 `accounts/<UUID>.json`。程序重启时读取该目录，文件无法解析时在管理页显示对应提示。新增或改名时先在同目录完整写入暂存文件，再原子替换目标文件。手动导出的 JSON 写入程序旁的 `exports/` 并显示完整路径。移动程序时，可把整个 `accounts` 文件夹一并移走。程序所在目录须可写。

### 游戏图像

Windows 版安装并启动后校验程序旁的 `images/StarRailRes.pack`，按清单自动下载缺失或损坏的全部游戏图像。角色头像、立绘、光锥、遗器来自 [StarRailRes 清单](../../../apps/src-tauri/star-rail-images.tsv)，货币战争局内装备、消耗品、对局角色图、羁绊图标与敌人图像来自 [Nanoka 货币战争图像清单](../../../apps/src-tauri/nanoka-images.tsv)。图像供所有账号共用。仓库和安装包仅包含来源、路径、字节数与 Git blob 校验值，不打包任何游戏美术原图。

Rust 校验下载的 PNG，优先转成无损 WebP，再按条目尝试 Zstandard 压缩并写入容器。每一步保留体积更小且像素无损的结果。启动时复用旧 `images/StarRailRes/` 中有效的 PNG 或 WebP，归档提交后清理对应散文件。窗口按需读取容器中的图片。TypeScript 启动校验并显示进度，文件齐全时可离线启动。普通页面禁止框选和全选文字、拖出图片以及默认右键菜单，编辑字段保留选择、复制和粘贴。

角色和账号装备图像来自 StarRailRes 4.7.0 的 [03907e7 提交](https://github.com/Mar-7th/StarRailRes/commit/03907e798b46f9eb109a1f882055cdf49ce3d374)。清单取自该提交文件树中的角色头像、完整立绘、光锥图标和遗器图标，共 567 张，源 PNG 合计约 372 MiB。桌面版的账号、对局和战斗预览均读取这套本地缓存。浏览器开发预览不包含游戏图像，未加载图像的位置以文字或首字占位显示。

Nanoka 图像来源为 `static.nanoka.cc/assets/hsr/`（包括 `gridfight/equipment/`、`avatarshopicon/`、`gridfight/icon/` 与 `monsterfigure/`）。清单沿用私有数据仓库 S2 `encyclopedia-4.6.54-679438c4be1c` 快照对应的素材记录，共 332 张 WebP（装备与消耗品 117 张、对局角色图 60 张、羁绊图标 35 张、敌人图像 120 张）。生成清单时先核对素材清单中的 SHA256，再记录图像长度和下载程序复用的 Git blob 校验值。原始 WebP 保留像素，并直接进入资源容器。

本机完整资源包含 899 张图片。离线验收用的副本保存在仓库根目录下的 `local-data/player-test-images/StarRailRes.pack`，由 Git 忽略。测试独立的 EXE 副本前，将资源包复制到该 EXE 旁的 `images/StarRailRes.pack`，启动后即可读取。容器和本机测试副本均在安装包之外。

## 对局

[对局页](match.md)记录开局、各阶段操作、模型观战及开发预览。[对局服务接入](match-commands.md)记录正式服务的联调约定。

## 战斗模式

战斗书签首次进入常规战斗，也可用 `?page=battle` 直接进入。两种模式都保留左侧行动轴、中间角色立绘和右页单位详情。横线下方的右页工具区用于切换模式和控制回放。点击轴上的单位查看其属性、装备和状态。

行动轴标题、当前行动栏和正在查看栏分别固定。列表超出页高时，用滚轮或按住鼠标上下拖动列表。上方或下方仍有条目时，对应边缘淡出。准备阶段中央展示所选单位，回放时展示当前行动者。点击行动轴可以独立检查右页单位。两处单位栏共用固定尺寸的头像槽，立绘和战斗详情在各自栏下方滚动。

创建演示对局并完成开局选择后，可在战斗页点“货币战争”，或在对局页点“查看本局战斗”。阵容预览使用本局前后台单位、局内装备及已揭示敌人。下次打开时按最新局面版本重建阵容。常规战斗配置在本次会话中保留。

战斗预览在行动轴标注“顺序待定”。`BattleResult` 的回放类型包含按实际行动排列的帧，每帧记录行动者、目标、伤害、事件和单位快照。正式战斗回放等待战斗服务接入。

## 桌面账号与图像接口

账号行迹的 `Skill.tab` 表示技能类型，`Skill.title` 表示技能名称。名称缺失时返回 `null`，界面在原有标题位置显示“战技名”“终结技名”等占位文字。

| 命令 | 输入 | 成功返回 |
| --- | --- | --- |
| `player_accounts` | 无 | 本地账号、角色档案及读取提示 |
| `player_inspect_account` | 文件名、JSON 原文 | 可编辑名称建议、库存摘要及导入报告 |
| `player_import_account` | 文件名、JSON 原文、账号名称 | 已保存的导入账号 |
| `player_generate_account` | 生成请求、可选种子和名称 | 已保存的生成账号及统计 |
| `player_account_catalogue` | 无 | 生成器支持的角色与光锥 ID |
| `player_rename_account` / `player_delete_account` | 本地文件 UUID；改名时附带名称 | 已更新的账号或删除成功 |
| `player_export_account` | 本地文件 UUID、文件类型 | 程序旁的导出文件路径 |
| `player_sync_game_images` | 图像校验进度通道 | 已验证的图像路径、待下载数量和失败原因 |

## 当前限制

| 场景 | 玩家现在能看到的结果 | 完整支持所需条件 |
| --- | --- | --- |
| 用自己的练度对局 | 已保存账号可分别创建演示对局，演示采用固定阵容样例 | 接入 Rust 会话服务和生效配置 |
| 查看数值、建议和回放 | 演示模型和阵容样例提供可操作的界面 | 接入经过核对的数值、策略与战斗事件 |
| 保存实战记录 | 本次演示会话内可记录观测值 | 接入持久化与建议评估 |
| 高倍率查看插画 | 书封和文字按显示倍率重绘，立绘、装备图和花饰的细节受原图分辨率限制 | 提供更高分辨率或矢量原稿 |
| 换设备查看 | 内嵌字体、固定画幅和等比缩放保持构图，窄窗口下文字随书页缩小 | 跨物理设备验收；WebView2 版本、字形抗锯齿与屏幕色彩仍会影响像素表现 |

书册外框已在 Windows WebView2 的 100%、150%、200% 设备像素比下验收。三组设置共采样九条从右页内侧延伸到书签表面的水平线，各线 Alpha 均为 255。窗口右下方书外采样点的 Alpha 均为 0。
