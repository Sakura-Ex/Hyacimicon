# Windows 玩家界面

[Hyacimicon](../../../apps/player/) 使用 Tauri 2、TypeScript 和 Lit。账号、对局和战斗在同一本书中切换。Windows 桌面版可导入、生成和管理本地账号。浏览器、对局和战斗当前使用预览数据。未接入的数据以短横线或空状态显示。

## 启动

在 Windows 安装 Node.js 22.12 及以上版本、npm、Rust MSVC 工具链、Visual Studio C++ Build Tools 和 WebView2。在仓库根目录运行：

```powershell
cd apps/player
npm ci
npm run tauri dev
```

`npm run dev` 在浏览器预览，`npm run build` 检查类型并构建页面，`npm run tauri build` 生成 Windows 程序和 NSIS 安装包。

书封、折口与纸层共用可缩放的矢量轮廓，侧边书签由 CSS 绘制。书册使用 1700 × 960 的逻辑画幅，根据可用宽高等比缩放，额外空间保持透明。安装包包含书册花饰、应用图标和两套 Noto SC 字体，字体许可位于构建产物的 `licenses/`。开发服务器可预览[设计稿素材](../../../design-drafts/player-app/assets/README.md)。

书册、标题和书签固定在窗口内，滚动条隐藏。角色列表、已保存账号和生成候选列表可用滚轮、键盘或按住鼠标拖动，列表标题和搜索框留在原位。角色资料、行迹与装备、对局内容、生成表单和战斗详情各自滚动。对局操作按钮、导入确认和生成提交留在各自内容区的下方。

### 装帧验收

修改书封、纸页或书签时，在调整前与最终截图验收时分别回看[初版战斗稿](../../../design-drafts/player-app/battle.png)及[装订素材](../../../design-drafts/player-app/assets/book/binding.png)。按同一画幅并排核对页宽、中缝位置、粉色页缘、页首花饰与书签外伸长度。检查三枚书签的根部伸入右页纸层，封板只在书签间隙露出。更换显示倍率后复查接缝及书外透明像素。

## 添加账号

在角色档案点“添加账号”，在页首切换文件导入或随机生成。

- **文件导入**。选择或拖入 reliquary-archiver 的 Fribbels v4 JSON，或应用导出、生成器产出的统一原始账号 JSON。[account-core](../account/README.md) 检查格式、练度和装备关系。右页显示角色、光锥、遗器、闲置库存数量以及导入提示。填写名称后点“导入并保存”，程序保留原文件、统一账号及可用的来源报告。
- **随机生成**。角色数量必填，支持 0 和内置资料允许的持有规模。可设置目标金数、五星统一星魂与专锥叠影、遗器质量及有效词条区间。右页可配置核心、角色池、光锥池、金数类别、集中度、角色覆盖和搜索预算，也可编辑或载入 [account-generator 请求 JSON](../account-generation/account-generation.md#生成条件)。种子可留空由程序生成，也可填写无符号 64 位整数。程序保存完整请求、实际种子、生成器版本、资料快照和结果统计。

保存成功后切换到新账号，显示原始练度、行迹和当前装备。“管理”可查看已保存账号及报告、改名、导出 JSON、确认删除，或用保存的请求和种子再生成。浏览器预览可查看界面，桌面版负责实际解析、生成和写入。

### 本地账号目录

每个账号保存为程序所在目录下的 `accounts/<UUID>.json`。程序重启时读取该目录，文件无法解析时在管理页显示对应提示。新增或改名时先在同目录完整写入暂存文件，再原子替换目标文件。手动导出的 JSON 写入程序旁的 `exports/` 并显示完整路径。移动程序时，可把整个 `accounts` 文件夹一并移走。程序所在目录须可写。

### 游戏图像

Windows 版启动时根据[图像清单](../../../apps/player/src-tauri/star-rail-images.tsv)校验程序旁的 `images/StarRailRes.pack`，并从 StarRailRes 下载缺失或损坏的角色头像、角色立绘、光锥和遗器图像。清单覆盖已选版本中这四类公开文件，供所有账号共用。安装包包含路径、字节数和 Git blob 校验值，游戏美术由应用启动后写入本地。

Rust 校验下载的 PNG，优先转成无损 WebP，再按条目尝试 Zstandard 压缩并写入容器。每一步保留体积更小且像素无损的结果。启动时复用旧 `images/StarRailRes/` 中有效的 PNG 或 WebP，归档提交后清理对应散文件。窗口按需读取容器中的图片。TypeScript 启动校验并显示进度，文件齐全时可离线启动。普通页面禁止框选和全选文字、拖出图片以及默认右键菜单，编辑字段保留选择、复制和粘贴。

图像来源固定为 StarRailRes 4.7.0 的 [03907e7 提交](https://github.com/Mar-7th/StarRailRes/commit/03907e798b46f9eb109a1f882055cdf49ce3d374)。清单取自该提交文件树中的角色头像、完整立绘、光锥图标和遗器图标，源 PNG 合计约 372 MiB。桌面版的账号和战斗预览也读取这套立绘。浏览器开发预览使用风堇和景元两张本地草稿立绘。该版本缺少帕姆王，以及预览所用的局内装备、羁绊和敌人图像。局内装备、羁绊和敌人的设计稿素材可在开发服务器预览。

本机完整资源包含 567 张图片，实测为 316.1 MiB。离线验收用的副本保存在仓库根目录下的 `local-data/player-test-images/StarRailRes.pack`，由 Git 忽略。测试独立的 EXE 副本前，将资源包复制到该 EXE 旁的 `images/StarRailRes.pack`，启动后即可读取。容器和本机测试副本均在安装包之外。

## 对局

对局页首固定显示当前位面、节点进度和整局血量。打开实战回填、滚动书页或进入本局战斗时仍可查看。局面返回 `planes` 时按位面排列节点，并用 `node` 定位当前位置。当前血量、血量上限分别使用 `health` 和 `maxHealth`。

前台、后台和备战席共用角色卡。每张卡片显示星级和当前装备。缺图时用装备名称或首字显示，悬停或聚焦装备可查看全称。左页查看阵容与羁绊，右页查看经济、建议、库存及商店。

演示局面的三个位面、20 个节点、星级、配装和血量用于验收布局。节点类型数量参考[游戏规则讨论稿](../../project/game-rules.md)，顺序和数值为演示样例。装备和羁绊名称取自 S2 `encyclopedia-4.6.54-679438c4be1c` 快照的 `items`、`traits` 条目。实战回填可更新演示局面的金币和血量。

## 战斗模式

战斗书签首次进入常规战斗，也可用 `?page=battle` 直接进入。页首切换模式；两种模式都保留初稿的左侧行动轴、中间角色立绘、右页单位详情和页首回放按钮。点击轴上的单位查看其属性、装备和状态。

行动轴标题和角色区域固定。列表超出页高时，用滚轮或按住鼠标上下拖动列表；上方或下方仍有条目时，对应边缘淡出。准备阶段中央展示所选单位，回放时展示当前行动者。点击行动轴可以独立检查右页单位。立绘按原稿展开，只有头像时以姓名旁的小图展示。

在战斗页点“货币战争”，或在对局页点“查看本局战斗”，即可使用当前账号的局面。该模式使用本局前后台单位与局内装备。两种模式分别保留行动游标与查看对象；局面版本变化后重新读取本局回放，常规战斗保留在本次会话中。

## 后端接入

在应用入口注入实现 `PlayerPort` 的适配器。桌面账号使用 `AccountPort` 的 Tauri 适配器，当前对局和战斗仍使用预览适配器。下表的账号命令已实现，对局和战斗命令为接入契约。参数名、可空字段与返回结构以类型文件为准。

账号行迹的 `Skill.tab` 表示技能类型，`Skill.title` 表示技能名称。名称缺失时返回 `null`，界面在原有标题位置显示“战技名”“终结技名”等占位文字。

| 命令 | 输入 | 成功返回 |
| --- | --- | --- |
| `player_accounts` | 无 | 本地账号、角色档案及读取提示 |
| `player_inspect_account` | 文件名、JSON 原文 | 可编辑名称建议、库存摘要及导入报告 |
| `player_import_account` | 文件名、JSON 原文、账号名称 | 已保存的导入账号 |
| `player_generate_account` | 生成请求、可选种子和名称 | 已保存的生成账号及统计 |
| `player_account_catalogue` | 无 | 生成器支持的角色与光锥 ID |
| `player_rename_account` / `player_delete_account` | 本地文件 UUID；改名时附带名称 | 已更新的账号或删除成功 |
| `player_export_account` | 本地文件 UUID、文件类型 | 程序旁的导出文件路径 |
| `player_sync_game_images` | 图像校验进度通道 | 已验证的图像路径、待下载数量和失败原因 |
| `player_match` | 账号 ID | 当前可见局面及该版本的建议 |
| `player_set_shop_lock` | 对局 ID、预期版本、目标锁定状态 | 新版本的完整局面 |
| `player_save_feedback` | 对局 ID、预期版本、实际操作 ID、按字段键索引的实测整数 | 已核对并重新评估的完整局面 |
| `player_battle_catalogue` | 无 | 可选角色、敌人及默认常规配置 |
| `player_battle` | 常规配置或货币战争局面引用 | 阵容预览或按发生顺序排列的行动帧 |

写入时原子核对对局 ID 和版本。成功后返回新版本，重复或过期写入返回版本冲突。每个反馈字段定义名称、当前值与允许范围，各项建议可提供预填值。玩家可修改预填值；后端负责确定最终状态。缺少建议时返回空数组。预览模式可以记录玩家填写的金币、整局血量和操作。

常规请求传入 `mode: standard`、`allyIds` 和 `enemyIds`。货币战争请求传入 `mode: currencyWars`、`matchId` 和 `revision`，后端据此解析阵容及专属规则。预览展示参战单位与装备，伤害、羁绊效果及行动顺序计算留待引擎接入。

`BattleResult.kind` 为 `preview` 时在行动轴列出参战单位并标注“顺序待定”，缺失行动值显示为短横线；为 `replay` 时提供行动帧与回放控制。

每个战斗帧携带行动者 ID、目标、伤害、截至该时刻的事件和单位快照。单位 ID 在帧内唯一，行动者引用本帧单位。游戏图片路径引用本地图像缓存。角色列表、行迹分组、库存、商店报价、建议、反馈字段和行动帧均按返回数组生成。

## 当前限制

| 场景 | 玩家现在能看到的结果 | 完整支持所需条件 |
| --- | --- | --- |
| 用新账号进入对局 | 新账号可在角色档案查看，示例对局使用预览账号 | 将账号转换为相应玩法的生效配置并接入对局 |
| 查看数值、建议和回放 | 缺失数值显示短横线，建议和事件显示空状态；阵容预览支持切换查看对象 | 接入经过核对的账号数据、策略结果和战斗事件 |
| 保存实战记录 | 本次会话可更新金币与操作，关闭后清空 | 接入持久化及按新版本重新评估的服务 |
| 高倍率查看插画 | 书封和文字按显示倍率重绘，立绘、装备图和花饰的细节受原图分辨率限制 | 提供更高分辨率或矢量原稿 |
| 换设备查看 | 内嵌字体、固定画幅和等比缩放保持构图，窄窗口下文字随书页缩小 | 跨物理设备验收；WebView2 版本、字形抗锯齿与屏幕色彩仍会影响像素表现 |

本轮在一台 Windows 设备上运行正式版，通过 WebView2 分别验证了 100%、150%、200% 设备像素比。在每种设置下，对三枚书签各采样一条从右页内侧延伸到书签表面的水平线。九条采样线的 Alpha 均为 255，窗口右下方书外采样点的 Alpha 均为 0。
