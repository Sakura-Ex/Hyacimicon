# 基础战斗模拟

`core/battle`提供独立于窗口的Rust库和`hcwa-battle`命令行入口。
输入已经合成的有效面板、动作和规则参数，返回战斗结果、事件记录或多次模拟统计。
Tauri可直接调用同一Rust库；账号转换与整局环境后续从各自模块接入。

## 当前能力

| 能力 | 已实现范围 |
| --- | --- |
| 行动时序 | 剩余距离/当前速度，普通Turn结束才重排，变速保距离，Cycle独立额度与到期比较 |
| 动作与资源 | 自动/脚本共用合法操作，终结技入Turn时扣能，再现进入后选招，追击直接Action，插入不推进AV |
| 直接效果 | 伤害乘区、逐命中暴击、嘲讽加权目标、治疗、护盾与持续时间 |
| 终止与复活 | 复活只扣本轮余AV至0，不改变时钟或单位距离；统一终局边界、行动保护、取消 |
| 批次评估 | 独立种子、逐局记录、胜败频率、95% Wilson区间、按种子重放 |

当前规则契约为`battle_v2`，旧`basic_v1`输入需要明确迁移。执行顺序见
[核心说明](../../../core/battle/README.md#scheduling-and-operations)。旧next_av主状态和动作前重排已替换。
完整Action后调度登记的后续动作；BattleEvent监听不依赖回放是否开启或截断。
行动轴只显示存活单位当前的一条常规位置。`ability_target`在动作入口绑定一次，
后续命中不因首击击杀而自动换人。

`mechanics`声明轮次额度、事件触发、韧性、终结技优先级和我方伤害系数。
0.3按负责人2026-11-17反馈单独应用于我方伤害结算一次，其底层游戏乘区尚未定位。
AI数值比较方向和同刻Cycle/单位先后仍是显式可选策略，不宣称已完成游戏实测。

`tools/config_actions.py`现可解析固定配置中的常规技能链，输出来源指针和执行操作。
实际核对过希儿继承普攻、PointB3下次行动提前与虚数织叶者普攻；使用指定有效面板，
不能把该探针标为完整角色战斗。完整导入遇到数值Modifier、未实现谓词和缺失能力会拒绝。
装备、羁绊、完整天赋及元素击破伤害/恢复还需接入；已有显式击破事件不等于这些规则已自动实现。

整局HP结算由整局环境维护，本库的`run_hp_loss`为未知，不填0，也不将角色剩余
HP当作玩家整局HP。预算耗尽按当前显式规则判败；程序行动保护和取消为
`incomplete`，不会混入胜败统计分母。

完整动作结束后，依次检查终局淘汰、已经发生的AV预算耗尽、取消与行动上限。
同一动作既耗尽预算又达到行动上限时，按预算判败并计入分母；如果预算尚未耗尽，
不能因为下一行动预计越界就把当前的行动保护或取消判成失败。

## 安装与运行

安装Rust工具链后，从仓库根目录进入`core/battle/`运行。该目录的`rust-toolchain.toml`固定
Rust版本，`Cargo.lock`固定依赖。

```powershell
cd core/battle
cargo test --locked
cargo run --locked --bin hcwa-battle -- validate examples/duel.json
cargo run --locked --bin hcwa-battle -- simulate examples/team-waves.json 17
cargo run --release --locked --bin hcwa-battle -- batch examples/duel.json 10000 20261114
```

场景和输出路径相对当前目录解析。输出为JSON，错误写入stderr并返回退出码2。可将结果重定向到仓库根目录下已忽略的`../../runs/`
目录。示例全部使用人工单位与参数；`duel.json`是理论胜率50%的暴击对决，
`team-waves.json`展示双波队伍，`revival-budget.json`展示声明的复活罚时和预算。
这些结果用于验证基础内核，不能当作真实角色的游戏胜率。

## 输入和结果

输入包含版本和来源描述、双方有效属性、动作、初始资源、波次、AV预算与行动上限。
`model::validate`校验完整输入并生成不可变`ValidatedScenario`；输入指纹随结果返回。
`engine::simulate`执行一场，`engine::simulate_cancellable`增加取消检查，
`batch::run_batch`调用同一引擎执行独立试验。复用接口不读取外部文件，不改玩家真实状态。

批次的`completed = wins + losses + draws`，仅completed进入频率分母；
`incomplete`、已启动后取消与未启动分别记录。没有完成样本时频率和区间为null。
种子在Rust中是u64，在JSON中使用十进制字符串，TypeScript应原样保留，
不能先转为Number再回传。单局重放使用ledger中该局的seed。

JSON解析启用浮点往返精度支持，同一Rust场景序列化再读回时保持数值、指纹和
AV边界结果一致。此约定不包含跨语言JSON规范化或截止点的近似容差。

有效面板的治疗加成、受治疗加成和护盾加成支持有限的`[-1, 1e12]`范围。
治疗的`1 + 治疗加成 + 受治疗加成`必须非负，入口会按已声明治疗动作检查所有
可能对象；自身治疗仅检查自身，敌方按每波分别检查。护盾仅使用施放者的护盾加成。
这些字段表达已合成面板，动态减益的施加与消失仍需另外实现。

## 验证与后续接入

测试覆盖手算公式、状态转换、边界预算、资源合法性、未知与错误输入、取消、
批次分母和完整种子重放；另外用固定上游表达式生成的18个合成向量核对公式迁移。
来源与许可记录见项目 README 的[参考与致谢](../../../README.zh-CN.md#参考与致谢)。

后续接入完整角色时，先完成账号/试用及模式参数的有效配置合成，逐项实现所需
机制并添加回归，再用可核验游戏记录对齐动作和结算。真实规则确认与软件测试
分别记录；只支持动作片段时不得标为整个角色已支持。
