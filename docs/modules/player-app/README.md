# Hyacimicon 窗口设计交接

玩家在 Windows 本地录入账号和当前局面，比较下一步可做的操作，在游戏中执行选择，再把实际结果记回工具。设计以给定时间内的整局通关为目标。先读[项目目标与玩家流程](../../project/overview.md)，建议结果与玩家反馈的约定见[系统设计](../../project/architecture.md)。

## 三个主界面

| 界面 | 玩家要解决的问题 | 布局重点 |
| --- | --- | --- |
| [账号](account.png) | 我的角色和装备能支持哪些方案？ | 统一入口支持文件导入和随机生成，可切换、管理账号并查看来源。左页检索角色，右页查看养成和装备。行迹按角色实际技能生成，可随条目数量换行。 |
| [对局](match.png) | 这一步买牌、刷新还是攒钱？ | 阵容与候选同屏，显示建议理由、成本与预期变化。前台 4 格、后台预留 6–9 格、备战席 9 格。商店五张报价收在一行；已穿装备随头像显示，详情贴着角色展开，库存和消耗品单列。 |
| [战斗](battle.png) | 换了方案后，谁先行动，属性与战果如何变化？ | 支持独立进入，也可从候选方案进入。保留常规线性行动轴，区分当前行动者与正在查看的单位，展示实时属性、装备、状态来源及持续时间。 |

## 用一个局面串起三个页面

静态示例中，前台和备战席各有一名一星景元，商店还有一名。右页并列招募、攒钱和刷新的后果。买入景元消耗 1 金币，余额从 37 到 36，合成二星后备战席从 4 人减至 3 人。玩家可先查看该候选的战斗试算，再回游戏自行操作。

[实战回填](feedback.png)是对局页的一种状态。玩家填写实际操作，核对余额、星级和席位后保存，工具再按更新后的局面评估。图中的建议、伤害和回填值均为设计样例。

三页沿用低饱和的风堇配色、书脊分栏和侧边书签，彩色立绘两侧淡入纸面。窗口保留应用图标、名称及标准窗口控制。参考图尺寸为 1600 × 960。
