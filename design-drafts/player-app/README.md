# Hyacimicon 窗口设计草稿

这份草稿供前端设计讨论。玩家在 Windows 本地录入账号和当前局面，比较下一步可做的操作，在游戏中执行选择，再把实际结果记回工具。设计以给定时间内的整局通关为目标。先读[项目目标与玩家流程](../../docs/project/overview.md)，建议结果与玩家反馈的约定见[系统设计](../../docs/project/architecture.md)。

## 三个主界面

| 界面 | 玩家要解决的问题 | 布局重点 |
| --- | --- | --- |
| [账号](account.png) | 我的角色和装备能支持哪些方案？ | 统一入口支持文件导入和随机生成，可切换、管理账号并查看来源。左页检索角色，右页查看养成和装备。行迹按角色实际技能生成，可随条目数量换行。 |
| [对局](match.png) | 这一步买牌、刷新还是攒钱？ | 运营策略依据账号资源和当前可见局面提出建议，规则解释购买成本、升星和席位变化。前台 4 格、后台预留 6–9 格、备战席 9 格。商店五个报价同屏，装备浮窗贴着角色。 |
| [战斗](battle.png) | 这次是谁行动、命中了谁？被查看的单位有哪些增益？ | 战斗独立打开。沿线性行动轴查看单位在对应时刻的属性、装备与状态，按实际发生的行动阅读战斗记录。 |

## 用一个局面串起三个页面

静态示例中，前台和备战席各有一名一星景元，商店还有一名。右页并列招募、攒钱和刷新的后果。买入景元消耗 1 金币，余额从 37 到 36，合成二星后备战席从 4 人减至 3 人。上阵人数和羁绊人数保持原值。运营神经网络独立于战斗模拟；玩家看完建议后在游戏中自行选择并执行。

[实战回填](feedback.png)是对局页的一种状态。玩家填写实际操作，核对余额、星级和席位后保存，工具再按更新后的局面评估。图中的建议、伤害和回填值均为设计样例。

三页沿用低饱和的风堇配色、书脊分栏和侧边书签，彩色立绘两侧淡入纸面。窗口保留应用图标、名称及标准窗口控制。参考图尺寸为 1600 × 960。

前端可直接使用同目录的[原型素材](assets/README.md)。
